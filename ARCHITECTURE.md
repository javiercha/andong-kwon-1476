No build step to run the site, no package manager, no framework: the same
discipline as the two sibling applications. `python3 server.py 8160` and it
runs; the build script only assembles `dist/` for Cloudflare.

## What happens when the page loads

1. The two TSVs are fetched and parsed by Relinkings' engine — NFKC, merge of
   edge endpoints missing from the node table, edge dedupe, choronym
   propagation, the generation index from the apex 權幸. About 300 ms.
2. **The leaf index.** Every edge cites a (volume, leaf, side); every node
   does too. A leaf's subgraph is its edges and their ends, plus anyone whose
   own row is filed there. Men whose own row is elsewhere are *restated*:
   drawn faded, listed with a link to their leaf. There are 363 leaves; the
   print has 363 (vol. 1 1a–57b, vol. 2 1a–54b, vol. 3 1a–71a) and every one
   is cited — `test/edition.test.mjs` checks this.
3. Two canvases are created from the shared module: the leaf in Inspection
   (`fitMin 0.12`, so a whole leaf is seen as a shape; `rows: 'local'`, so
   each man sits one row below the father the leaf names — the corpus-wide
   generation index disagrees with the leaf's own edges for about three
   thousand men) and the lineage in Graph (Sebo's floor of 0.6, so names
   are never a smear).
4. The right pane of Inspection shows the notebook's June 2025 render by
   default — the drawing the tables were originally checked against — with
   the live drawing one click away; the choice is remembered in the browser.
   A man filed on a leaf by the node table with no relation cited there is
   listed with a ∅ mark and left off the drawing.
5. The hash routes: `#/leaf/1/6a`, `#/leaf/1/6a/C206472` (a man selected),
   `#/person/C206438` (his kin on the Graph tab), `#/graph`.

## The one drawing convention

The question in the brief — can Graph be one module shared by Sebo and this
edition without breaking either — is answered in `web/js/samhan-graph/`.
Its README gives the whole account; the short form:

- Sebo's `graph.js` (195 KB) is the drawing *and* five things that are not
  drawing (tool sidebar, autocomplete, disambiguation modal, kin
  expand/collapse, merge bar).
- Relinkings had already ported the drawing alone (73 KB) and hardened it.
- `samhan-graph.js` 2.0 is that port with the page bindings replaced by
  options and events, plus everything else Sebo's Graph view offered: the
  schemes and every picker, the roles on a path, custom patrilines, the
  hand-drawn line, multi-selection, the floating actions. The tools sidebar
  is `samhan-graph-tools.js`, driven through a provider; export (SVG, PNG,
  TSV) is `samhan-graph-export.js`.
- Relinkings adopts it by swapping one `<script>` for two (the module and
  `adapters/relinkings-canvas.js`); nothing else changes. Staged on its
  `graph-module` branch and previewed on the tailnet (port 8190).
- Sebo adopts it through `adapters/sebo-provider.js`, which rebuilds the
  `SeboGraph` facade the rest of Sebo calls; `graph.js` and `export.js` are
  no longer loaded. Staged on its `graph-module` branch, previewed read-only
  on the tailnet (port 8180). Merging is the owner's call.

Distribution is vendoring with a version stamp (`VERSION`, `scripts/vendor.sh`
writing `web/VENDORED`), because none of the three sites has a package
manager and this keeps it that way. When the skin (`samhan.css`) gets the
same treatment, the three sites will share three files by copy and by
version: the engine, the canvas, the skin.

## What is deliberately not here

- **A write path to the tables.** The edition is a reading copy. The one
  thing a visitor can send is an error report, and that
  lands in the editor's own ledger (`reports.py`), never in the tables: a
  report is a warrant for a correction made by hand, not the correction.
- **A database.** 7,617 people and 8,729 relations fit in a tab; every query
  the notebooks asked is a bounded traversal. Relinkings' README argues this
  at length and the argument holds here.
- **A model in the rendering path.** The tables are read as they are; no model sits between them and the page.
